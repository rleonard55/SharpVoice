# SharpVoice User Guide

[← Back to the README](../README.md)

Detailed setup and everyday use. Start with the [quick start](../README.md#quick-start) if you have just installed SharpVoice.

## First run

Install the latest [Windows release](https://github.com/rleonard55/SharpVoice/releases/latest), or extract its portable ZIP. No separate .NET runtime is required. For source builds, see [Development](development.md).

SharpVoice starts directly in the system tray. Double-click the microphone icon, or right-click it and choose **Open settings**, to open Settings.

1. Allow microphone access for desktop apps in Windows Settings → Privacy & security → Microphone.
2. The default installer and portable ZIP from **0.1.1 onward include Tiny Q5 English (`tiny.en-q5_1`)**. SharpVoice verifies the included model before using it, so first-run dictation does not require a model download. Existing valid cached models are preferred, and other speech models download when selected. Source builds and older packages may still download the default model. **AI cleanup starts off: None (Transcription Only)**. No AI account or cleanup model is needed to dictate. Choose an AI provider in Settings only if you want cleanup, selected-text editing or Ask AI. Existing saved provider/model choices are preserved when upgrading.
3. Focus a text field in Notepad or another app. **Hold Ctrl + Alt**, wait for the start tone, speak, and **release either modifier**. Either key order and left/right modifier keys work. Release the remaining keys before starting the next recording. The HUD displays recording, transcription, refinement, and insertion status.
4. Applying settings saves them and closes Settings to the tray; validation or save errors keep the form open. Closing Settings also leaves the app in the system tray. Right-click its tray icon to open settings, pause/resume the microphone, copy the last result, or exit. Cancel dictation appears in Settings only while dictation is active.

SharpVoice automatically offers a four-step setup wizard on the first launch of a new profile: **Microphone → Shortcuts → Optional AI → Practice**. Use **Skip Setup** or close the wizard at any step; it will not appear automatically again. Interrupted setup remains pending. Existing profiles retain tray startup. The wizard is not available from Settings; use the regular settings pages for later changes.

Microphone testing starts only when requested and stops when you leave the step, switch apps, minimize or close setup. Explicitly applied microphone/AI preferences are retained even if you later skip setup. AI setup and shortcut customization use the existing Settings pages; Apply or close Settings returns to the wizard. Practice uses the local speech model and displays its transcript inside the wizard, without selection capture, AI, history or insertion. Click Start/Stop Recording or hold your dictation shortcut. Leaving the wizard cancels practice; it never resumes automatically. The wizard does not require practice or an AI account before Finish.

To start automatically, open **Settings → General → Start on sign-in**, choose **On**, then Apply. It is **Off by default**, registers only for the current Windows user, and opens in the tray. Choose Off and Apply to remove the registration. Keep the portable executable in a permanent location; after moving it, launch it from the new location and Apply again to update the startup path. Windows Startup Apps can independently disable it.


### Ask AI

hold **Ctrl + Alt + Shift**, speak a question or request, then release. SharpVoice instructs the model to return only the requested answer/content—no preamble, acknowledgement, unsolicited closing summary or signoff—and inserts the result into the original control. Requests such as “output,” “write,” or “print” ask for the content directly; named works should be complete when permitted, preserving line and stanza breaks. Requested summaries, code or lists remain allowed. Highlighted text supplies optional context in this mode. The current AI backend/model is reused; backend `none` cannot answer requests. Empty speech and Whisper no-speech markers such as `[BLANK_AUDIO]` produce no AI request or inserted text.

Both shortcuts can be selected or recorded independently in **Hotkeys**. Adding Shift to an active default Ctrl+Alt recording promotes that same recording to Ask AI, with one start/stop cue and one insertion. The mode stays latched until the gesture ends; release all shortcut keys before trying again. Duplicate shortcuts and Ask shortcuts contained within the Dictation shortcut are rejected because they would prevent Dictation from starting. Older settings receive the new default; if it conflicts with an existing dictation shortcut, Ask uses a nonconflicting F9/F10 fallback while preserving the user's dictation choice.

### Smart Ask AI (optional)

open **Settings → General → Smart Ask AI**, choose **On (Speak Questions)** and a preferred Edge voice, then **Save Changes**. It starts **Off**, preserves your saved choice and reuses your AI provider/model. A question such as “What does this mean?” shows a persistent response pill and reads the answer, without pasting or replacing selected text. “Could you rewrite this?” and “Output the Invictus poem” remain writing requests and insert their content. Selected text is context. Intent and content come from one AI request; ambiguous intent is shown in the pill for you to decide. Malformed structured responses fail visibly without pasting. Ordinary dictation and explicit VS Code code-preview commands keep their existing behavior.

The response pill offers **Reply by Voice**: click, wait for the start tone, speak, then click **Stop Recording**. **Type Reply** reveals a text field and **Send** as a fallback. Replies retain recent conversation context, including the original question and clarification, and are displayed and read aloud in the same popup. They never paste automatically; use **Insert** explicitly. Empty recordings or failed requests retain the previous answer so you can retry or type instead. Conversation context stays in memory until SharpVoice exits. Closing the popup dismisses it and cancels active work; the next Ask AI hotkey continues the active thread. Use **Conversations → New Conversation**, select a recent thread, delete a thread, or clear all. Restoring an old answer does not restore its old paste target.

The pill also has **Stop, Replay, Copy, Insert and Close**. Stop cancels an active reply or stops readout. It shows full scrollable text, the AI model and speech status, and appears without stealing focus. Insert explicitly returns to the captured text field, validates its process/control/selection and refuses a changed target; Copy lets you choose another destination. Starting a new recording stops speech and waits for playback to finish before opening the microphone. Keep Ready input is suspended while reading, so it cannot supply speech playback as pre-roll. Pause, Close, exit and disabling Smart Ask cancel playback. Readout is limited to the first 12,000 characters; the complete answer remains readable/copyable.

### Live transcription

**Audio → Live Transcription → On (Local Draft)** shows local Whisper drafts while speaking, including voice replies and editor recordings. This defaults On; choose **Off (Waveform Only)** to reduce CPU use. Recent words can revise, and the pill shows the latest words as speech grows. After Stop, the full recording is transcribed for the final result; draft text is never pasted or sent to AI. Slower models/hardware may update less often or suspend drafts. A prerecorded Tiny Q5 fixture on the development machine updated about every 2.5–2.9 seconds under the release Native AOT runtime (1.6–1.9 seconds under managed .NET); this is not a latency guarantee.

### Session conversations

general Ask AI context is shared by hotkeys, popup replies and the editor panel. Code/document attachments and Connected Ask use separate scopes. Threads are held only in SharpVoice memory, excluded from saved dictation history, and cleared on app exit. There are bounded recent threads/turns and prompt context; the panel indicates omitted earlier material. Changing provider/account in SharpVoice retires incompatible context. If you switch Claude/Gemini accounts outside SharpVoice, start a New Conversation or restart SharpVoice before continuing; those CLIs do not expose a reliable account-change signal. Provider/CLI storage policies remain separate from SharpVoice's conversation storage.

### Edge voices

included with SharpVoice and prepared automatically on first use—no Python installation, setup command or account is needed. The private runtime stays in SharpVoice’s per-user cache; it does not change your PATH or install system packages. Missing/failing Edge speech falls back to your installed Windows voice and reports that in the pill. Edge voices send answer text to Microsoft and need a network connection. Text goes to the private helper through stdin, not process arguments or plaintext files. Temporary MP3 audio is removed after playback, cancellation or failure. If both engines fail, the answer stays available on screen. Packaging details and pinned upstream dependencies: [private speech runtime](../vendor/edge-speech/README.md).

### Short dictation

AI cleanup is skipped for ordinary dictation with **fewer than 8 words** by default; 8 or more words use your configured AI backend. In **AI & models → Minimum words for AI**, set a threshold from 0–1000; **0 always refines**. Ask AI and selected-text edits always use AI regardless of length. Bypassed text skips AI cleanup but still uses your personal dictionary and exact voice snippets, so custom AI cleanup/formatting instructions are also skipped. The HUD/status identifies skipped cleanup without reporting an AI model as used. New and older configurations default to 8, while an explicit 0 is preserved. Words are whitespace-separated tokens containing a Unicode letter or digit; contractions and hyphenated words count once, punctuation-only tokens do not count.

### Settings guidance

Dropdowns use readable names, such as **Tiny (English, Fastest)**, **ChatGPT (Account Sign-In)** and **Clipboard (Recommended)**. Hover over a setting’s ⓘ button for guidance, or click it to keep the explanation open. Keyboard users can Tab to the button and press Enter or Space; Escape dismisses help. Quiet-speech gates, model tradeoffs, AI cutoffs, prompts, shortcuts, insertion and startup each have contextual help. Labels map to the same saved IDs, so existing settings remain compatible.

### Download a local cleanup model

Open **AI & models**, choose **Local AI (Offline Cleanup)**, select a model, and click **Download Model**. The native bar shows transfer bytes/percentage and SHA-256 verification before Ready. **Cancel Download** removes its partial file; retry starts a new download. Valid existing weights are checked and reused. Downloads continue in the background when you switch tabs, close/Apply Settings or dictate. Changing the provider/model cancels the old selection; exiting SharpVoice cancels outstanding downloads. Downloading does not save or activate your draft choices—use **Apply Settings** to keep your provider and model preference.

| Local Model | Download | Tradeoff |
| --- | --- | --- |
| [Qwen 2.5 0.5B Q4_K_M](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF) | 491 MB | Smaller, faster; used by Auto |
| [Qwen 2.5 1.5B Q4_K_M](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF) | 1.12 GB | Larger; needs more memory and CPU |

Both run on the CPU offline after download. Files are saved per user under `~/.sharpvoice/models`. Exact byte sizes and official LFS SHA-256 values are pinned in `LocalAiModels`; transfers install atomically only after integrity checks. Normal local refinement can still prepare a missing model on first use; **Test Connection** never downloads weights.

### ChatGPT cleanup reasoning

Ordinary dictation cleanup requests Low reasoning effort on verified compatible model IDs (`gpt-6-luna`, `gpt-6-sol`, `gpt-6-astra`, `gpt-6.1-sol`), including when Auto selects one. Ask AI, selected-text edits, code-mode/editor requests, connected actions and conversation replies retain their existing reasoning behavior. Other providers and custom model IDs are unchanged. This preserves AI cleanup and its word threshold; a latency reduction is not guaranteed.

### Faster dictation

In **AI & models → Speech Processing**, choose **Fast (Short Dictation)** to try a shorter Whisper encoder window for recordings up to 15 seconds. It uses your selected model and the entire recording; longer recordings, wake activation and wake-session resolution retain Standard processing. Fast is opt-in because it can change accuracy. Your existing AI cleanup threshold remains active; AI/network latency is additional. Clipboard insertion is faster than typing. In **Insertion**, lower Insertion Delay if your target app supports it; saved delay preferences are respected. After an ordinary insertion, Settings status shows its elapsed time. The ⓘ beside **Last Result** gives the last successful release-to-insertion dispatch breakdown (preparation, local transcription, AI/rules, insertion), kept only in memory. This measures dispatch, not the target app's next rendered frame. It excludes time waiting for explicit VS Code diff approval.

**Test the selected AI connection:** In **AI & models**, choose a provider and model, then click **Test Connection**. It uses the choices currently shown, without Apply or saving unrelated preferences. Success shows the responding model and request time; failure details are in the adjacent ⓘ help. The button becomes **Cancel Test** while running, with a 60-second deadline. A tiny fixed public request is sent; no speech, selection or clipboard text is included or pasted. Remote tests count toward account allowance. Local AI requires already downloaded, hash-valid model weights and does not download them during a test. Changing the provider/model, starting sign-in/dictation, leaving the tab or closing Settings cancels an outstanding test. A completed nonempty model reply proves connectivity; punctuation differences are allowed.

Settings tabs highlight on hover without changing the selected section. Settings is organized into **Audio, AI & models, Prompts, Hotkeys, Insertion, and General** tabs. Choose a microphone, adjust the gate with a slider while watching the live input meter, select standard or compact Q5 Whisper tiny/base/small, enter or choose an AI model, and customize general or per-mode instructions. Hotkeys supports Ctrl + Alt, F1–F24, and recorded modifier/key combinations. Switching microphones and applying reconnects capture while idle; a disconnected saved microphone remains selected until you choose another. Apply your Whisper model selection in **AI & models** to prepare the selected download in the background. **Default insertion uses clipboard paste**, which transfers the completed text atomically. The optional `typing` mode sends paced Unicode key events rather than bursts of 32 characters. Configured function-key events and matching custom shortcut keys are reserved globally; modifier down/up events remain available to Windows and the target app. Pause closes microphone capture in either mode. Resume automatically reopens capture only in Keep Ready; On Hotkey stays idle until the next shortcut or explicit preview.

Highlight text before holding the hotkey to **edit it by voice**: say “make this shorter” or “change the date to Friday,” then release. SharpVoice uses the highlighted text as the source and your speech as editing instructions, and replaces the selection only while the original field, range and text remain unchanged. Without a selection, ordinary dictation cleanup applies. An AI backend is required for selected-text editing. Selection discovery reads native EDIT/UI Automation controls without copying or changing held keys. Unsupported editors may expose no selection; classic EDIT documents and UIA selections are limited to 32,000 characters. Password text is excluded.

**AI & models** loads your account’s concrete model names/IDs and marks the recommended economical choice. The default remains **Auto**, now favoring the lowest known ChatGPT credit cost available (currently Luna when your catalog offers it); explicit model choices are preserved. Unknown models fall back to the catalog order with cost/speed marked unknown. The Settings hint and compact pill HUD show the selected/resolved model, and response metadata updates the name if the server reports a different model. ChatGPT subscription credits are distinct from Platform API prices; actual speed and included usage vary. Current policy references: [OpenAI models](https://learn.chatgpt.com/docs/models) and [credit rates](https://learn.chatgpt.com/docs/pricing), checked 2026-11-01.

The app and tray use your **faceted microphone artwork**, with transparent backgrounds: silver while idle or processing, red while recording, and amber for errors or warnings. The executable uses the silver icon too. A short rising chime signals recording start; a distinct falling chime signals stop, after the audio tail finishes. Cue output and PCM buffers are prepared and silently primed at startup, then reused on a dedicated audio thread to avoid per-cue device startup delays. A soft, fading success ding plays after successful insertion or selection replacement. Silence or an empty transcription plays a warning beep and skips AI refinement and insertion.

Branded icon resources include 16–256 px frames with a matching scale and baseline for all states. Transparent PNGs, source artwork and the generation prompt are documented in [Data/Branding](../Data/Branding/README.md); rebuild ICOs with `scripts/build-brand-icons.ps1`. ChatGPT account controls appear only for ChatGPT OAuth: **Sign in** when signed out, **Sign out** when signed in. Account controls live in Settings and follow the selected backend. Account actions are disabled while authentication is in progress.

Forms, the HUD, and the tray context menu follow the Windows app light/dark preference. Settings navigation and action buttons use the same monochrome Segoe icons as the tray, with text labels retained. Open forms update when Windows changes theme. Owner-drawn menu entries include Microsoft accessibility labels and native checked states.

Tray actions include monochrome icons for Settings, pause/resume, Copy and Exit. Icons use [Windows' Segoe MDL2 glyphs](https://learn.microsoft.com/en-us/windows/apps/design/iconography/segoe-ui-symbol-font), with theme-aware colors and text labels retained for accessibility.

**Microphone activation:** In **Audio → Mic Activation**, **On Hotkey (Default)** leaves the microphone device unopened while idle. Hold a shortcut and wait for the start tone before speaking; the tone confirms native capture is ready. Releasing the shortcut finishes the existing 50 ms audio tail and releases the device before processing. Releasing during startup cancels the attempt without transcription, insertion or a false start tone. **Keep Ready (Faster Start)** keeps local capture active and a rolling 250 ms memory buffer to preserve speech just before the key; idle audio is not transcribed or sent to AI. Device startup adds latency in On Hotkey; choose Keep Ready if faster starts matter more. New and older configurations default to On Hotkey, while an explicitly saved Keep Ready choice is preserved.

Opening Settings does not activate the microphone in On Hotkey. Use **Audio → Preview Applied Mic** to temporarily check the saved microphone and noise gate. Preview is local, has no transcription, and ends on Stop Preview, leaving Audio, closing/applying Settings, starting dictation or pausing. Changing the microphone dropdown requires Apply before preview uses that device. Keep Ready remains active independently of temporary preview until paused or the app exits.

### Optional wake phrases

Open **Audio → Wake Phrases** and select **On (Listen for Wake Phrases)**. A lightweight local speech detector triggers checks using **the same Whisper model selected in AI & Models**. No separate keyword model is downloaded. Preparation, cancellation and Retry appear in that window. Say **“Hey SharpVoice”** for Ask AI, or **“Hey SharpVoice Dictate”** for dictation, and continue speaking immediately. Buffered audio preserves the beginning while Whisper checks; activation can take a moment, especially with larger models. The longer phrase wins, so **Dictate** directly after **Hey SharpVoice** selects dictation. Both phrases are editable. Wake recordings stop after **2 seconds of silence** by default (adjustable 1–10); the matching hotkey also stops them, and Escape cancels. Hotkey Hold/Toggle preferences keep their existing behavior.

Wake phrases are **off by default**, including after upgrading existing settings. When enabled and ready, they keep the microphone listening locally even if Mic Activation is On Hotkey. Idle audio stays in a bounded memory buffer. Whisper does not run during silence; detected speech triggers local prefix checks and uses more CPU. No idle AI-provider requests run. The automatically verified local speech detector also ends wake recordings independently of the transcription noise gate, so a quiet-speech gate does not treat steady room noise as continued speech. The microphone pauses during readout and wake recognition suspends while processing or using an editor voice session. **Pause Microphone** in the tray suspends capture. Recognition accuracy depends on the selected Whisper model, microphone, room and phrase; this does not identify the speaker. Ask AI still requires a provider or Connected Ask AI; dictation works with AI cleanup off.

The noise gate defaults to **−65 dB** to allow quiet speech. More negative values admit quieter audio; moving toward 0 rejects more audio. If quiet speech is rejected, lower the gate and Apply settings. Previously saved thresholds remain configurable. The live meter marks the draft threshold, dims sound below it, and highlights the portion above it in blue. The label reports the current dB difference and updates immediately with slider/field changes; Apply settings to use the previewed threshold for dictation.

The original foreground window, process ID and focused control must still match before insertion. Changing apps during processing stops insertion. Completed text stays in the preview; use **Copy last text** to recover it. Insertion into elevated apps can be blocked by Windows. Clipboard mode replaces your clipboard; it requests exclusion from Windows clipboard history/cloud sync but cannot control third-party clipboard managers.

The HUD uses Direct2D/DirectWrite with a GDI fallback. Model loading starts while you hold the dictation key. Audio uses pooled buffers with ownership retained until transcription finishes; working-set pages are trimmed after insertion.

The optional **`embedded`** refinement backend uses LLamaSharp and CPU Qwen2.5-0.5B-Instruct Q4_K_M. Its first use downloads and verifies a **491 MB** model; later refinement runs locally. It can take tens of seconds and may edit less accurately than ChatGPT. Your full master prompt is preserved. Model weights and context are released after each request. AI cleanup is off on a fresh installation; saved provider preferences are preserved. The paid OpenAI Platform backend was excluded at your request.

## Writing tools and recent dictations

Open **Settings → General** for **Personal Dictionary**, **Voice Snippets**, **App Profiles** and **Recent Dictations**. Each editor keeps a draft until **Save Changes**; Cancel discards it.

- **Personal Dictionary:** map a spoken phrase to its preferred spelling. Corrections apply once to final ordinary dictation, even with AI off; preferred terms also hint local Whisper. Ask AI and selected-text editing keep your instructions intact.
- **Voice Snippets:** give saved text an exact spoken trigger, such as “insert my signature.” A whole-utterance match inserts it verbatim without AI; casing and terminal punctuation are ignored. Snippets do not expand in Ask AI or selected-text edits.
- **App Profiles:** match an executable name, such as `Outlook.exe`, and override the provider/model, writing mode, word threshold or additional instructions. Blank choices inherit global settings; a changed provider with a blank model uses Auto. Accounts and local models must be prepared in AI & Models first. Settings are captured when recording starts.
- **Recent Dictations:** compare the transcript (or selected source) with its result, copy, delete, clear, or retry with a chosen provider/model. Retry always asks AI regardless of the word threshold, updates the preview/history, and never pastes automatically. Local retries require downloaded weights. The newest 50 text entries are kept, with no audio. History is **In Memory (Until Exit)** by default; **History Storage → Save Locally (Encrypted)** opts into current-Windows-user encrypted storage. Choosing In Memory removes saved disk history.

In **Hotkeys → Recording Gesture**, **Hold to Talk (Default)** preserves push-to-talk. **Toggle** starts with one press and finishes with another, for both Dictation and Ask AI. Release the keys between presses. An optional **Silence Auto-Stop** of 1–30 seconds ends toggle recording when sound stays below the applied noise gate; **0 disables it**. Maximum recording duration and cancellation still apply. These options do not change On Hotkey microphone activation.

The pill HUD places its title at the top left and smaller, muted, right-aligned model/status metadata on the same row. The lower area shows up to two lines of the current text. The pill is 85% opaque and dismisses about 0.9 seconds after a successful paste; other outcomes stay visible longer. Drag anywhere on the pill to move it without taking keyboard focus from your text field. The position is saved when you release it and remembered after restarting SharpVoice. Each new recording appears on the monitor containing its target app, keeping the saved relative placement within that monitor. With no saved placement it uses bottom center; it does not follow later focus changes during the same request. Placement stays within the nearest monitor’s usable area if your display arrangement changes. Dragging pauses dismissal until release.

## VS Code conversation panel

Update the companion extension through **Settings → General → Plugins → VS Code → Update**, then reload VS Code. Desktop and VSIX **0.2.0 / editor protocol 3** must be updated together. Click the **SharpVoice microphone** in the Activity Bar or status bar, or run **SharpVoice: Open Conversation Panel**.

The panel offers **Ask AI**, **Dictate Code** and **Edit Code**, voice start/stop/cancel, typed replies, persistent clarification questions, recent conversations and New/Delete/Clear controls. Generic Ask AI can run without a source file and shares the desktop's general conversation. **Include Current File** explicitly adds bounded document context in a separate scoped thread. Code edits always capture fresh source and require the existing diff review and explicit Apply; remembered conversation does not authorize a change.

Use **Dock Right** to open VS Code's native Move View picker; choose **SharpVoice**, then **Secondary Side Bar**. VS Code remembers that placement. Its extension API does not provide automatic default right-side placement. Closing/hiding the panel or losing window focus cancels its active recording/request. An explicitly approved edit already being applied waits for its receipt; a lost connection reports Outcome Unknown so you can check the document before retrying; completed conversations remain in desktop memory and resynchronize when reopened. App restart/disconnection clears the panel's old transcript. No Webview/extension transcript persistence is used.

## Google AI Studio API Key

In **Settings → AI & models**, choose **Gemini (AI Studio API Key)**, then **Manage API Key**. Paste your key into the masked field and choose **Save API Key**. Use **Test Connection**, then **Apply Settings** to activate the provider. Reopen Manage API Key to replace or remove the key; an existing key is never displayed. Cancel keeps the current key.

**Auto** uses `gemini-3.1-flash-lite` for economical text processing. The model choices also include Gemini 3.5 Flash-Lite and Gemini 3.8 Flash; you can type an exact API model ID available to your Google project. Switching between API and sign-in providers resets the model to Auto. Google API quota/billing applies separately from a Gemini subscription; there is no automatic fallback between API-key and Antigravity providers. [Google API keys](https://ai.google.dev/gemini-api/docs/api-key), [models](https://ai.google.dev/gemini-api/docs/models) and [pricing](https://ai.google.dev/gemini-api/docs/pricing).

The key is protected by Windows DPAPI for the current user in `%USERPROFILE%\.sharpvoice\gemini-api-key.dpapi`, separately from JSON preferences and history. Requests use Google's official Gemini endpoint with the key in an HTTP header, never the prompt or URL. Provider error bodies are not displayed. Google receives the text and context needed for your request; its API data policies apply. Cleanup, selected-text edits, Ask AI, Smart Ask AI and VS Code requests share the same prompts as other providers. Empty speech and short-cleanup skips do not load a key or make an API call. Only a complete successful answer can be inserted; blocked or token-limited output is rejected. Changing/removing the key clears in-memory conversation context. Connected Ask AI continues to use its separate ChatGPT sign-in.

## Connected Ask AI

Open **Settings → General → Connected Ask AI** to opt into existing callable Windows Codex integrations. Discover tools, explicitly allow capabilities, sign in to ChatGPT, and enable the feature. Unavailable tools are hidden by default; **Show Unavailable** reveals them when needed. Choose individual tools or **Allow All Available Tools**, then **Save Changes**. Allow All grants the currently discovered supported tools, including collections larger than 64; newly added tools still need permission. Ctrl+Alt+Shift then opens a branded activity/answer window with typed or voice follow-up. Each supported external change requires an exact before/after review and its own on-screen confirmation. Existing-record update/delete actions remain unavailable; actual tool/profile compatibility varies. [Setup, review rules and compatibility](connected-ask.md).

## VS Code voice coding

The companion extension adds language- and document-aware code entry and refactors in **native Windows VS Code with local files**. In SharpVoice open **Settings → General → Plugins**, select VS Code or VS Code Insiders, and choose **Install** or **Update**. The plugin is bundled in SharpVoice; no separate download is needed. The manager shows the installed/included versions, verifies installation, and prompts you to reload the editor. Opening Plugins only checks status; installation requires its own button. Missing editors must be installed first. It checks standard user/system installation locations and PATH; **Refresh** checks again. A newer plugin is preserved.

**Antigravity IDE** is also listed, with experimental compatibility for its local VS Code-compatible Windows editor. It requires the editor's extension CLI and the same supported VS Code APIs; a real Antigravity host acceptance test remains outstanding. This is separate from using Antigravity for Google AI sign-in. Install/Update uses the editor's extension installer, without changing AI providers or accounts. Close cancels an ongoing operation; refresh afterward to check whether the editor finished it. You can still install a locally built VSIX through **Extensions: Install from VSIX…** for custom editor locations. Choose an AI provider globally or in an editor app profile first.

Use the **microphone/edit buttons above the editor** or the **SharpVoice status-bar microphone** to start; click **Stop** when finished. Follow-up questions offer an **Answer by Voice** button that returns to the source and starts another recording after the capture-ready tone. The status distinguishes Starting Microphone from Recording; missing readiness produces an explicit error after 15 seconds.

Alternatively, run **SharpVoice: Dictate Code (Start / Stop)** or run **SharpVoice: Edit Code by Voice (Start / Stop)**. Wait for the start tone, speak, then run the same command again or **SharpVoice: Stop Recording**. Examples: “insert a customer ID property,” “wrap that in a try-catch,” “only run that if the customer exists,” and “convert that to a switch.” Both editor commands can add or change code using the available context. Missing conditions or genuinely unclear intent prompt a clarification. No highlight is required. With default Nearby Code context, SharpVoice uses the current document (up to 32,000 characters) or a bounded nearby target, including the original cursor position. An explicit highlight takes priority.

If you highlight code before answering a clarification or while speaking, the plugin refreshes that target before generation. The original instruction is retained. **Every code result previews**, including simple insertion. Inspect the diff and choose **Apply Voice Edit** or **Cancel Voice Edit**; one Undo restores the original text. Apply returns to the original source editor and rechecks the saved document version/range. There is no automatic save, build, terminal execution or clipboard fallback. Changing the source/window/editor, closing the diff, cancellation and disconnect invalidate pending work. Internal terminal/sidebar keyboard focus is not reliably exposed by VS Code; the explicit preview/Apply step prevents automatic source edits based on retained editor identity.

Start commands have user-assigned VS Code shortcuts; Escape cancels only an active editor session. Existing global SharpVoice dictation/Ask shortcuts and saved hold/toggle preferences stay separate. The editor commands use explicit start/stop recording. Remote/WSL/SSH/container and web editors are outside this first milestone.

**SharpVoice: Context** controls Selection Only, Nearby Code (default) or Current Document. Selection Only never expands an empty cursor into document context; select a target for edits in that mode. Source comes from the unsaved buffer, bounded to 32,000 UTF-16 characters, with language, formatting and bounded diagnostics. The provider receives the basename rather than the document URI; the extension retains URI/version only locally. No repository scanning or other-file reads. Editor code/context is kept in session memory and excluded from saved dictation history. Model output may be incorrect; inspect it and run normal project checks. See [extension setup and build details](../extensions/sharpvoice-vscode/README.md).

## AI refinement

**New installs default to None (Transcription Only)**. ChatGPT OAuth is an optional refinement backend with AI model `auto`. Audio stays on-device; the transcript and refinement instructions are sent to ChatGPT. Backend `none` disables refinement requests for local transcription only. Window titles are not sent.

The default cleanup instructions come directly from **[DefaultPrompts.cs](../src/SharpVoice.Core/DefaultPrompts.cs)**, compiled into the application. No loose prompt file is required beside the published executable. Fresh installs pre-fill **Prompts → General Instructions** with that text. Existing saved instructions, including an explicitly empty field, are preserved. The pre-filled document is an editable cleanup template and is sent once for dictation cleanup. It is excluded from selected-text/code editing, including after edits. Existing additional preferences and per-app instructions retain their previous behavior. Writing-mode context, optional general instructions and instructions for the detected/selected mode follow the master prompt; changing the source master prompt requires rebuilding the app.

- **ChatGPT subscription (experimental):** use **ChatGPT sign in**, complete the browser flow, select `chatgpt_oauth`, leave **AI model** set to **`auto`**, and Apply. Auto selects the lowest-known-credit-cost available model in the signed-in account's Codex catalog (catalog priority is the fallback when cost is unknown) and caches discovery for ten minutes. You can enter an explicit model instead. The original `gpt-5.1-codex` default is migrated to `auto` when settings load; other explicit selections are preserved. Access and model availability depend on the account and service. This uses the spec's Codex public OAuth client/backend, not a supported general-purpose OpenAI Platform API contract. The browser callback shows a branded light/dark result page; success appears only after tokens are exchanged and saved. Declines and failures show a clear result without provider diagnostics, and callback parameters are removed from the address bar. Port **1455** must be available; SharpVoice does not terminate another program using it. **ChatGPT account → Sign in again** starts another browser authorization without requiring logout; the current login stays available until replacement credentials are successfully saved. A cancelled or failed replacement keeps the current login. The browser may reuse its own provider login. **Sign out** removes this app's saved session locally; it does not revoke other devices' sessions.
- **Claude subscription via Claude Code:** install/update the official native Windows Claude Code executable to **2.1.293 or newer** (`claude update` for an existing install). Choose `claude_code` in AI & models, then **Claude sign in**. Anthropic's unmodified terminal/browser flow owns login, refresh and credentials. SharpVoice does not collect Claude.ai OAuth tokens. Sign out affects the shared Claude Code login on this device. Auto explicitly selects `haiku`; Sonnet, Opus and explicit Claude model IDs are available, subject to your plan and usage limits. The actual model ID is shown after a successful response. Claude returns the completed response rather than streaming partial text in SharpVoice; CLI startup adds latency. This optional backend requires a separately installed CLI; New installs start with no AI cleanup; saved provider choices are preserved.

- **Gemini subscription via Antigravity:** install Google’s official native [Antigravity CLI](https://antigravity.google/docs/getting-started), version **1.4.12 or newer** (`agy update`). Select **`gemini_antigravity`** in AI & models and use **Google account → Open Google sign-in**. Complete Google’s own terminal/browser flow and close that window when finished; closing it is not proof of login. A successful request verifies the connection. Google account → Sign out in Antigravity opens its own `/logout` command; this affects the shared Google CLI login. Auto pins **`gemini-3.8-flash-medium`**, recommended for efficient text processing; an Argon option and explicit Gemini model IDs are also available. Availability and Google plan/credit limits apply. Dictation, selected-text editing and Ask AI use the same existing prompts and insert only a complete successful result. Google owns tokens and refresh; SharpVoice does not read, copy or store them and does not fall back to API-key billing. The standard `%LOCALAPPDATA%\agy\bin\agy.exe` installation is detected even when it is absent from PATH.

Antigravity uses a SharpVoice-owned `~/.gemini/config/agents/sharpvoice-text-only.md` agent with default components excluded and no tools. Existing edits to that file are refused rather than overwritten. Speech, selected text and prompts go through stdin, not process arguments. Global hooks, MCP, automatic rules, other custom agents and enabled sidecars are incompatible with this text-only integration and are refused before dispatch. Metadata/skills-only plugins and disabled sidecars may stay installed; slash-command/skill expansion is disabled. Existing Google configuration is never disabled or rewritten by SharpVoice. If preflight reports an incompatible customization, adjust it in Antigravity or use another SharpVoice backend.

**Google CLI retention differs from Claude:** Antigravity can save its own local conversations/history and apply its own service retention/telemetry settings. SharpVoice does not have a verified per-request flag to disable that storage, so this optional backend does **not** provide memory-only transcript retention. A short retention notice remains visible in AI & models before use; model help provides the full context. It also adds CLI startup latency and returns the completed response rather than partial previews.

Groq has been removed. Saved `groq` profiles migrate to ChatGPT/auto while preserving other preferences. Claude uses [Anthropic's documented CLI interface](https://code.claude.com/docs/en/headless) and [authentication guidance](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use), rather than offering third-party Claude.ai login. Dictation/selection content is sent through stdin; tools, hooks, MCP servers, project settings, slash commands, browser integration and session persistence are disabled. Temporary mode-instruction files are cleaned up after requests. Anthropic's own account retention/usage policies still apply.

Cloud errors, empty responses, truncated responses and interrupted streams do not fall back to silently inserting a partial refinement. The raw transcript is retained for manual recovery. Cancellation during Unicode insertion can leave text already sent to the target; the app never retries automatically.

If ChatGPT reports that a model is unavailable, choose `auto` and Apply, then retry. Authentication can succeed while a model request fails. The original prototype's HTTP 400 was reproduced as `model_not_found` for the retired default; automatic model discovery fixes that selection. Until refinement succeeds, **Copy last text** lets you recover the raw transcript.

ChatGPT access/refresh tokens are stored in `%USERPROFILE%\.sharpvoice\session.json` as a **DPAPI-encrypted binary blob** (despite the spec's filename). Only the current Windows user can decrypt it. The app creates its own session and does not read Codex/ChatGPT application credentials. Refresh is serialized and runs five minutes before expiry on a one-minute check, with an additional check before requests. Non-secret settings are source-generated JSON in `%USERPROFILE%\.sharpvoice\config.json`; models live in its `models` subfolder. SharpVoice conversations stay in memory until exit. Dictation history is also in memory by default; Recent Dictations can optionally save encrypted history locally. Text explicitly inserted or copied is handled by the destination app or clipboard. The optional Google Antigravity runtime can additionally persist its own conversations/history as described above. The optional Claude Code backend runs with session persistence and prompt history disabled; Anthropic’s own runtime diagnostics and service retention policies also apply.
