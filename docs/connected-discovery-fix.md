# Connected discovery and blank transcription — 2026-11-01

User report: Connected Ask AI discovery failed with “Codex response exceeded its limit.” Whisper could surface `[BLANK_AUDIO]` as ordinary text. The user clarified that this recognition output should simply produce no text, AI response or insertion.

Root cause: CodexRpc used a shared 1,048,576-character line limit for tool results and discovery metadata. `mcpServerStatus/list` pagination counts servers; an individual aggregator server can expose enough tool schemas to exceed that limit. Both a synthetic 240-tool catalog and metadata-only discovery against the actual Windows Codex profile reproduced the error during catalog loading. No tool was called or email content read. Logs: `connected-catalog-red-tests.log` (135/136), `connected-catalog-real-red.log`.

The real-profile rerun then exposed two more discovery-only boundaries: valid tool schemas exceeded the shared JSON depth of 24, and the catalog exceeded the arbitrary 1,000-tool cap. A 40-level synthetic schema and then a 1,200-tool fixture reproduced those failures (`connected-catalog-depth-red-tests.log`, `connected-catalog-count-red-tests.log`). A metadata-only measurement found 1,750 tools across seven connected servers, a 6,230,398-character response and 2,336,814 schema characters. It invoked no tools or inference turns (`connected-catalog-counts.log`).

Fix: catalog discovery has a coherent budget of 16,777,216 response characters, JSON depth 128, 4,096 tools and 16,777,216 retained schema/description/name characters across pages. Ordinary responses retain their original size/depth limits, request bounds, deadlines, operation whitelist and schema checks. The maximum 64 selected permissions and action/approval rules remain unchanged. Lines accumulate in a bounded StringBuilder rather than repeated growing-string copies. The parser retains a document only for the current message and clones just the returned result. Overflow errors now suggest a concrete recovery action.

Whisper results and segment previews pass through one shared non-speech annotation filter. Blank/silence/background annotations become empty text. Existing empty-transcript handling stops before AI, history and insertion. Valid text and unrelated code brackets remain intact; audio thresholds are untouched. All voice adapters and live drafts use the shared engine.
