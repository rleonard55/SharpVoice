# Windows Installer and GitHub Release Updates

Build SharpVoice 0.1.0 as a per-user Windows x64 Velopack installer, portable ZIP and update feed using pinned SDK/tool 1.2.161. Keep the native AOT app, transparent branded icon and bundled inference/speech/editor assets. Exclude symbols, build paths, models, credentials, diagnostics and user data from release packages. Preserve existing data under the user's `.sharpvoice` directory during install, upgrade and uninstall. Registration uses the installed stable launcher; uninstall removes only its own startup registration.

The user authorized building the installer and release updates, chose automatic installation when idle, and requested two independent controls: **Automatic Updates** (default On), and **When an Update Is Found** (Notify Only / Download Automatically / Install When Idle; default Install When Idle). Manual Check, Download and Install/Restart remain explicit actions when automatic updates are off. Turning automatic updates off cancels automatic downloads and prevents pending automatic installation. Re-enabling respects the saved action.

Use fixed public GitHub Releases from `rleonard55/SharpVoice`, stable `win-x64` channel, with no embedded GitHub credential or private-feed token. Check shortly after startup and every six hours; failures are nonfatal and visible in Updates. Public checks cannot work until the repository and a published release are public. Build and test local update packages now; create a draft release only after verification, keeping the repository private.

Automatic installation requires a downloaded verified package, at least 60 seconds of application inactivity, no voice/editor/authentication/AI/speech work, and no settings, review, answer or tools window. Evaluate and quiesce on the UI thread, stop accepting new voice starts, exit the message loop and fully dispose audio/workers before invoking Velopack apply/restart. Disable Velopack's implicit apply-on-startup so Off and Notify Only cannot be bypassed by an earlier download. Notify/download modes never auto-restart. Restart clears memory-only conversations; explain this in Updates.

Use Velopack's managed APIs behind a narrow injected interface so policy, scheduling, cancellation and restart eligibility can be verified offline. Do not invent a custom executable-replacement protocol. Test real installer/bootstrap/update/uninstall using an isolated test package identity/location and a non-recording fixture; do not replace the user's running development app or install over user preferences. Report any remaining clean-Windows or code-signing limitations honestly.

Produce reproducible scripts and a tag/manual GitHub Actions workflow that builds/tests/packages and uploads **draft** release assets. It must not change repository visibility or automatically publish a release. Release metadata uses a public noreply identity and deterministic mapped build paths; retain third-party license notices. Package code signing is optional until a publisher certificate is configured; unsigned builds must be identified as such.
