# Dictation hotkey through the editor plugin

Approved in chat: only the configured Dictation shortcut should enter the VS Code plugin's document-aware workflow; Ask AI stays general. The active file name, language, unsaved code and selection/nearby context must reach the code provider. Results open a diff and require Apply; Undo remains native. No clipboard paste is used for this path.

Use the existing authenticated local editor bridge and preview/apply flow rather than separate VS Code keybindings, which cannot represent all supported modifier-only/custom desktop shortcuts. The plugin subscribes while its trusted local editor window is focused, reconnects after desktop startup, and captures fresh context on a correlated desktop request. Reject stale starts after key release, expiry, client change or focus change. Preserve hold/toggle gestures; an Ask AI promotion cancels the code handoff and resumes the existing general Ask path. Do not fall back to paste in a supported editor when the plugin is unavailable.

Implementation decisions: protocol 4 and plugin 0.2.1 ship together; pending handoff has a 5-second timeout. Focused-window subscription releases ownership when inactive so another VS Code window can connect. Explicit plugin commands continue working. Require a current editable local document; do not fall back to a cached previous source when no editor is active. When VS Code keeps its active source while the terminal or sidebar has focus, visibly return to that current source and capture it fresh; no text goes to the terminal. Readonly/remote/untrusted contexts refuse code changes. Tests use isolated profiles/desktops, synthetic capture and providers; no real app/editor session or credentials are changed.
