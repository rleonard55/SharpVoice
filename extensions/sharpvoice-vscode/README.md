# SharpVoice for VS Code

Use the SharpVoice Activity Bar microphone, status-bar entry, or **SharpVoice: Open Conversation Panel** for a persistent voice/text workspace. **Dock Right** opens the native Move View picker: choose SharpVoice and Secondary Side Bar once. VS Code remembers the placement.

With VS Code in the foreground, use your configured desktop **Dictation** shortcut to open a document-aware code request. The plugin reads the current file name, language, unsaved text and selection, then inserts proposed changes directly into the working file with pending-change highlights. Hold/toggle gestures and custom shortcuts follow the desktop settings. The configured **Ask AI** shortcut opens read-only Ask AI in the plugin, with the same hold/toggle gesture. It automatically includes the current filename, extension, language and highlighted text. **Include Current File** adds bounded surrounding/file content; without a selection it sends file details only unless that option is enabled. Outside a supported IDE, Ask AI uses the desktop. If the bridge is unavailable, the desktop shows a connection message instead of pasting into source.

Choose Ask AI, Dictate Code or Edit Code. Speak starts recording; wait for the tone, speak, then Stop Recording. Questions stay in the panel with Reply by Voice and a text composer/Send fallback. Typed code requests skip microphone capture. Code results update the working file immediately. Keep making voice or typed requests, edit or test the code, then choose **Accept All** or **Revert All** for the current file. **Review Changes** opens an optional cumulative diff. Each insertion and batch reversal supports native Undo; SharpVoice never explicitly saves or executes code (your VS Code Auto Save settings still apply).

Ask AI with an active file uses a separate conversation scoped to that file; without an active file it shares the desktop's general conversation. Document attachments/code threads are scoped separately; fresh document context is captured and validated on each coding request. New/recent/delete/clear controls manage bounded in-memory conversations. Closing/hiding the view or switching applications cancels unfinished work but preserves completed exchanges until the desktop app exits. App restart clears the panel's transcript. No extension/Webview transcript persistence is used.

Desktop Live Transcription displays provisional local Whisper drafts in the pill and panel. Draft words can change; the final full recording is transcribed after Stop. Audio Settings can disable drafts. Drafts are never pasted or sent to the LLM.

Install/update through SharpVoice Settings → General → Plugins, then reload VS Code. Extension **0.3.3** requires desktop editor protocol **9**. Windows native local trusted workspaces only; WSL/remote and virtual documents are unsupported. The focused editor window subscribes automatically; inactive windows release the channel, including after an in-flight insertion finishes. Context permission is configurable as Selection Only, Nearby Code (default, up to32,000 characters), or Current Document when within bounds. Explicit selections take priority; nearby/document targets let named-block edits work without highlighting everything.

The editor-title microphone/edit controls and Command Palette commands remain available. SharpVoice uses its selected provider/model; no provider credentials are stored in this extension.

Pending review is tracked separately for each document. Hiding the panel, switching files or reconnecting to SharpVoice preserves it. Cancel stops only the active request. Accept All keeps the text and clears its review markers. Revert All reverses independent AI changes while preserving unrelated manual edits; overlapping manual edits are marked as conflicts and kept for your review. Undo/Redo may mark pending changes as conflicted when their ownership becomes ambiguous.

Pending review is checkpointed in local workspace extension storage, up to 2 MiB total. Closing a document or reloading the IDE preserves its review history. Resume Review restores markers and baselines without overwriting source; files changed externally are marked conflicted. Untitled checkpoints remain available and can be matched to an open document with the same contents. Normal IDE save/hot-exit behavior controls unsaved source text. Accepting changes does not save files. Discard Recovery removes saved inactive review; Accept All Files clears active and saved review.

Exact editor shortcuts work when spoken in Dictate/Edit Code, typed in the code composer, or invoked from the Command Palette:

| Shortcut | Target and behavior |
| --- | --- |
| **Document** | Add idiomatic documentation to the selection captured when the request starts, or the entire file if initially unselected. Uses the selected AI provider; whole-file requests retain the 32,000-character limit. |
| **Comment** | Comment the initial selection using the editor's language configuration. Does nothing when initially unselected. |
| **Uncomment** | Remove comments from the initial selection using the editor's language configuration. Does nothing when initially unselected. |
| **Explain** | Explain the initial selection or entire file in the conversation, without changing source. Uses the AI provider and the 32,000-character context bound. |
| **Format** | Run the configured native selection/document formatter on the initial target. Use normal Undo to reverse formatting. |

Names are case-insensitive and accept terminal speech punctuation. Longer requests remain normal AI instructions. Native commenting follows VS Code's selected-line behavior, including excluding the next line when the selection ends at column zero. Comment/Uncomment never call the AI provider. Document, Comment and Uncomment changes remain pending for Accept All/Revert All. Format behaves as a normal editor operation, preserving manual input during asynchronous formatting; it can mark overlapping pending AI edits as conflicted. Install extension 0.3.3 and the matching protocol-9 desktop build together.

Language validity guards reject Comment and inline Document in strict JSON, JSON Lines, CSV and TSV; use Explain instead. JSONC (including settings.json in JSONC mode) retains comment support. AI replacements targeting JSON/JSON Lines must produce a valid complete document before insertion, even when only a fragment was selected. Uncomment can restore selected commented-out JSON code only when the resulting complete JSON is valid; strings containing URLs or comment-like characters stay unchanged. Other languages use their native editor support and provider instructions; this is not a general compiler or schema checker.

## Follow-up questions

Ask AI and code-edit clarification questions appear in a highlighted card above the reply box. A distinct two-note cue plays once for a new live question when audio feedback is enabled. Restoring or refreshing a conversation does not replay the cue.

The AI can supply up to four suggested replies. Click a button to send that reply, or answer by typing or voice. No reply is selected automatically. Buttons are tied to their question, and clicking them never accepts pending edits. Code questions remain attached to the active source session; canceled code questions stay in history without active reply buttons.


## IDE workflow tools (0.3.3)

Expand **Code Tools** in the panel or use the Command Palette. The same package serves VS Code, VS Code Insiders and experimental Antigravity.

- **Individual review:** Accept/Revert Change CodeLens controls sit above pending blocks. The panel lists file/line locations and jump/accept/revert controls. Say/type **Accept This**, **Revert This**, **Next Change**, **Previous Change**, **Accept All Files** or **Revert All Files**. This/Change commands target the block containing the cursor. Manual conflicts are kept for review, and stale controls cannot reverse moved code.
- **Fix / Explain Error:** Choose the actual diagnostic at the cursor, or select from current errors/warnings. Fix proposes a correction for its selected range; Explain Error is read-only. Diagnostics before/after the last edit appear in the panel and may update asynchronously from the language service. These counts are not proof of successful compilation.
- **Related Files:** Explicitly select up to four existing local workspace files as context. Their unsaved contents are shared with the selected provider, bounded to 8,000 characters per source with visible truncation markers. **Edit Related Files** asks for one coordinated instruction and edits those selected files sequentially with fresh context/version checks. Each target is limited to 32,000 characters. Completion waits for desktop receipts. Cancellation/failure stops later files and reports how many files changed; earlier edits remain pending. Review per block/file or across all files; this is not an atomic multi-file transaction.
- **Test This:** Select source or place the cursor inside a function, then choose an existing/new test-file path. Source stays unchanged; generated tests enter the target as pending edits. Source-under-test context is retained through clarification and validation. Keep total source plus instructions within 32,000 characters. Related test examples and project guidance help identify the framework; the model may ask when it is unclear. New files remain unsaved until normal IDE saving.
- **Run Tests:** Pick an existing native workspace task. SharpVoice executes only the task you select and reports its actual exit code, or unknown/canceled status. It does not invent test commands or run a model-proposed shell command. Configure the project's test task through the IDE if none is available.
- **Recovery:** Use **Resume Review** after reload, or **Discard Recovery** to remove saved history. Resolve deferred recovery for a file before generating more edits in it. Changed files are marked conflicted rather than automatically restored. Missing/untitled targets retain their checkpoints. Recovery stores source/baselines locally; conversation and audio remain outside this storage. A storage-limit/write warning means current review may not be recoverable after restart.
- **Navigation:** Say/type **Go to Calculate**, **Select Calculate**, **Select This Function**, or **Next Error**. Native document/workspace symbols and diagnostics define targets. Ambiguous names/diagnostics open clickable pickers with locations; unavailable language providers produce a clear status.
- **Custom Shortcuts:** Configure `sharpvoice.shortcuts` in personal or workspace settings, e.g. `{ "Add logging": "Add structured logging using this project's conventions; preserve behavior." }`. Phrases match exactly, ignoring case and terminal speech punctuation. Built-in commands win; expansions are AI instructions and never shell commands. **Configure Shortcuts** opens the setting.
- **Explain Changes:** Read-only explanation of bounded before/after pending hunks, including conflict labels. The pending-change list jumps to the corresponding code. Large reviews explicitly report how many hunks were included.
- **Conventions:** Applicable workspace `AGENTS.md`, `.editorconfig` and common formatter/config files supply bounded literal guidance. Add personal/workspace preferences with `sharpvoice.codingInstructions`. The panel lists context/guidance files. User intent and language-validity rules win; repository instructions never execute tools. External paths, credential-like files and junction escapes are excluded from automatic related context.

Review recovery is local to this workspace and editor installation. Provider/model settings continue to live in the desktop app. App and extension must be updated together for protocol 9. Actual Antigravity host compatibility remains experimental; automated native host verification uses isolated VS Code.

The Blue + Indigo panel palette adapts to editor light/dark themes, preserves high-contrast editor colors, highlights questions in amber and recording controls in red.
